---
title: Rotate a password
description: Rotate a project's database password, an app secret, the Cloudflare token or a Scaleway key - and the deploy restarts exactly what changed.
---

import { Aside, Steps } from '@astrojs/starlight/components'

## A project's database password

<Steps>

1. Generate a new value and put it in `anvil.env` (`<NS>_RW_PASSWORD` or `<NS>_RO_PASSWORD`; `scripts/anvil-secrets set` does it and re-encrypts):

   ```sh
   python3 -c 'import secrets;print(secrets.token_hex(24))'
   ```

2. Rebuild the generated Secrets, then change the user in MariaDB:

   ```sh
   python3 -I scripts/make-secrets.py
   scripts/node.sh atlas-users
   ```

3. Deploy the project. Its `atlas-db` Secret changed, so `node.sh deploy` restarts exactly the workloads that use
   it (`config changed: restarted <ns>/<name>`):

   ```sh
   scripts/node.sh deploy <ns>
   ```

4. Re-encrypt and commit: `make secrets-encrypt`.

</Steps>

Between steps 2 and 3 the app still holds the old password in its connection pool and new connections fail;
keep the gap short.

## An app secret (`apps/<ns>/prod.env`)

Edit the value, `python3 -I scripts/make-secrets.py`, `scripts/node.sh deploy <ns>`, `make secrets-encrypt`. Every
key the app reads must be present, or the pod can't start ([rule 14](/reference/app-rules/#14-every-referenced-secret-exists-first)).

## The Cloudflare API token

Create a new token with the [same scope](/components/edge/#the-cloudflare-api-token-local-and-least-privilege),
put it in `anvil.env`, run the Cloudflare scripts once to prove it works (they're idempotent), delete the old token,
`make secrets-encrypt`. Nothing on the server changes: it never had the token.

## Scaleway keys

<Aside type="caution" title="Create keys with no expiry, and remind yourself to rotate them">
An expired Scaleway key fails **silently**: SMTP answers `535 … The token is expired` and mail just queues. On
the original server an app's email key was created with an expiry and stopped working days later without an alarm. Create
API keys without an expiry, and put a dated rotation reminder into `HUMAN.md` instead.
</Aside>

Rotate the backup key the same way as any secret (`BACKUP_S3_*` in `anvil.env`; `make-secrets.py` copies it into the
Secrets of the backup jobs and health-watch): new key with the same policy (write objects + send email,
nothing else), `make-secrets.py`, deploy the namespaces that run backups, trigger one backup job to prove it
(`kubectl -n atlas create job --from=cronjob/atlas-backup zz-backup-test`, then delete the job), delete the old key.

## The Claude credential

A subscription token from `claude setup-token` is valid about a year: keep a `HUMAN.md` reminder a month before it
expires. When it lapses the autopilot can't run (you still get called: it fails safe). Put the new value in the
vault (and wherever the auto-commit script reads it), then check with
`claude -p "say ok" --max-turns 1`.
