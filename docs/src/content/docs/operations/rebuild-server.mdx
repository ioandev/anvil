---
title: Rebuild the server
description: Replace the node from scratch - re-enable the image pipeline, replace the instance keeping the IP, redeploy everything and restore every database.
---

import { Aside, Steps } from '@astrojs/starlight/components'

Everything needed is in the repo plus the **restore bundle** (`.data/`, gitignored: database dumps, file tarballs; the
origin-pull CA and Origin CA keys have encrypted twins in git) and your age key, which decrypts `anvil.env`. Nothing is read from the old
server.

<Aside type="danger" title="Ask first">
Replacing `scaleway_instance_server.k3s` means downtime for every site. Operators (human or Claude) never apply a
plan that destroys or replaces the server or `scaleway_instance_ip.public` without the owner's explicit OK.
</Aside>

<Steps>

1. **Refresh the restore bundle**: the newest dumps from the off-site bucket (admin key) into
   `.data/<ns>/db.sql.gz`, plus file data. Check you can decrypt the secrets (`make secrets-decrypt`).

2. **Silence everything**, including `Watchdog` (so the off-box watchdog stays quiet), for longer than the work.

3. **Re-enable the image pipeline**: delete `infra/local.auto.tfvars` (or set `image_pipeline = true`), then
   `make fetch`.

4. **Plan and read it**:

   ```sh
   make plan TFARGS='-replace=scaleway_instance_server.k3s'
   ```

   Expect the image chain to be created and the server replaced; the **IP must not be replaced** (it's a separate
   resource and survives).

5. **Apply**: `make apply TFARGS='-replace=scaleway_instance_server.k3s'`. The image import takes several minutes;
   Ignition then installs k3s, Traefik's config, the origin-pull TLSOption, swap and Tailscale on first boot.

6. **Wait for the node**: `scripts/node.sh kubectl get nodes` ready; Tailscale joined (or run `sudo tailscale up`
   once if you gave no auth key); `scripts/node.sh disk` shows the full disk.

7. **Deploy everything**: `make apps` (regenerates Secrets, deploys every platform and app namespace).

8. **Restore data**: `scripts/node.sh restore-db <ns>` for each project with a database; `node.sh load-pvc` for file volumes.

9. **Verify**: `/overall` 200, every site 200 through Cloudflare, `/cluster?strict=1` 200, a backup job run by hand
   succeeds.

10. **Clean up**: `make cleanup` (deletes the import bucket, snapshot and image again), `make secrets-encrypt` (the
    Terraform state changed), commit. Let the silences run out rather than expiring them
    ([why](/operations/silence-alerts/#removing-a-silence-safely)).

</Steps>

## Changing only Butane or node manifests

You don't need a rebuild for that: apply the change on the live node by hand (k3s re-applies anything dropped into
`/var/lib/rancher/k3s/server/manifests/`), then `terraform apply` for the in-place `user_data` update so the next
rebuild gets it. Validate Butane locally first (render `ct_config` with `strict = true`).

<Aside type="note">
anvil's planned `anvil down` / `99-teardown` is the other direction: delete everything billable (instance, IP,
buckets, registry tags, DNS records). See [Bootstrap skills](/quickstart/bootstrap-skills/).
</Aside>
