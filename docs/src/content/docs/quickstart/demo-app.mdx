**anvil-demo** is a tiny guestbook that runs on anvil to show the platform working, live: **break it → an alert
fires → the autopilot fixes it.** Source in `demo/`, manifest in `apps/anvil-demo/app.yaml`.

## What it is

| Part | Details |
|---|---|
| **Web** (`dist/server.js`) | 2 replicas, UID 6000, port 8080 behind the Ingress for `demo.<domain>`. Lists the latest entries with a form; new entries start *pending*. Rolling deploys (`maxUnavailable: 0`), `preStop` sleep 5 s. |
| **Worker** (`dist/worker.js`) | singleton (`Recreate`, 1 replica), UID 6001, port 8081 (probes, metrics, admin; never public). Every 5 s it takes the queue, marks entries *approved* and counts them per day. |
| **Database** | `anvil_demo` in the shared MariaDB, via the platform's `atlas-db` Secret (the `_rw` user). Schema created at start with `CREATE TABLE IF NOT EXISTS` under a `GET_LOCK`, so two copies starting together are safe. Tables `entries`, `entry_queue`, `daily_stats`. Covered by the nightly atlas backup; UID 6002 is reserved for a separate backup job. |
| **Metrics** | web on `:9090/metrics` (a Service port only, not on the Ingress), worker on `:8081/metrics` |
| **Image** | one distroless image (TypeScript on Node.js 24, `fastify`, `mysql2`, `prom-client`, no frontend build). No shell, any numeric non-root UID, read-only root filesystem, no secrets inside. |
| **Secrets** | `atlas-db` (DB_*) and `anvil-demo` (`ADMIN_TOKEN`, generated by `anvil-secrets` from `sites.yaml` `generate:`) |

It follows every [app rule](/reference/app-rules/). One deliberate difference from rule 11's "same endpoint":
liveness is `/healthz` (process only) and readiness `/readyz` (database too), so a database outage takes pods out of
rotation instead of restart-looping them.

## Endpoints

| Method | Path | What |
|---|---|---|
| GET | `/` | the guestbook page (latest 20 entries, totals, form) |
| GET | `/api/entries?limit=20` | latest entries as JSON (1–100) |
| POST | `/api/entries` | `{"name","message"}` → 201, or the HTML form → 303 to `/`; rate limited per client IP (default 5 per 60 s per pod → 429 with `Retry-After`) |
| GET | `/healthz` | process alive, never touches the database: **liveness** |
| GET | `/readyz` | database reachable and schema ready: **readiness** |
| POST | `/admin/break` | `{"mode": "hang" \| "slow" \| "errors" \| "crash" \| "stuck"}`, header `X-Admin-Token` |
| POST | `/admin/fix` | clears every mode, on every web pod and the worker |

Without `ADMIN_TOKEN`, `/admin/*` answers 404; it is limited to 30 requests a minute per IP. The client IP is
`CF-Connecting-IP` (else the socket address); `X-Forwarded-For` is ignored. Names are 1–40 characters, messages
1–280; control and bidi-override characters are refused; everything is HTML-escaped and the page sends a strict CSP.

## Break modes

`/admin/break` on the public URL breaks **every web pod** (it fans out through the headless Service
`anvil-demo-web-peers`; `"all": false` breaks only the pod that answers). The break is held **in memory only**, so a
restart, the autopilot's main move, always fixes it.

| Mode | What happens | What heals it |
|---|---|---|
| `hang` | every request (incl. `/healthz`) stalls forever | **Kubernetes alone**: liveness fails 5× → restart in ~2.5 min |
| `slow` | every response takes 8 s: readiness (5 s timeout, 3 failures) fails, liveness (10 s) passes | the **autopilot** (restart) |
| `errors` | everything but `/healthz` returns 500, readiness fails | the **autopilot** (restart) |
| `crash` | the process exits with status 1 once | **Kubernetes alone**: the container restarts at once |
| `stuck` (worker) | the worker stops processing; `/healthz` stays 200, its heartbeat goes stale | the **autopilot** (restart the worker) |
| `BREAK_ON_START=1` (env) | a new release crash-loops; the old pods keep serving | the **autopilot** (`kubectl rollout undo`) |

## How anvil watches it

`sites.yaml` gives the probes (`https://demo.<domain>/` and `/readyz`, through Cloudflare) and the scrape targets
(`metrics:`). The alerts it trips:

| Alert | Fires when | After |
|---|---|---|
| `SiteDown` | a probe of `demo.<domain>` fails | 5 min (suppressed for 10 min after a Deployment changes) |
| `ServiceUnavailable` | fewer ready web/worker pods than wanted | 5 min (same suppression) |
| `AnvilDemoWorkerStuck` | the worker's heartbeat (`anvil_demo_worker_last_run_timestamp_seconds`) is older than 120 s | 2 min more: ~4 min after the worker stops |
| `PodCannotStart` | a pod in CrashLoopBackOff etc. | 5 min, counted once the pod is 10 min old: ~15 min |
| `PodRestartingOften` | > 3 restarts in 30 min | at once, for pods older than 10 min |

Metrics include `anvil_demo_http_requests_total`, `…_request_duration_seconds`, `…_db_errors_total{op}`,
`…_rate_limited_total`, `anvil_demo_break_mode{mode}` and the worker's heartbeat, processed count, queue depth and
`_stuck`. For a shorter stage show you can add a demo-only rule (`AnvilDemoDown`: the demo's probe failing for 1 min).

## The live-demo script

Before the talk: the app is deployed, the autopilot is running, and nothing was broken in the last 30 minutes (so
restart counts in `PodRestartingOften`'s window are clean). On the presenter's laptop:

```sh
export DEMO=https://demo.example.com
export TOKEN="$(grep '^ADMIN_TOKEN=' apps/anvil-demo/prod.env | cut -d= -f2-)"   # never on screen
brk() { curl -s -X POST "$DEMO/admin/break" -H "X-Admin-Token: $TOKEN" -H 'content-type: application/json' -d "{\"mode\":\"$1\"}"; echo; }
fix() { curl -s -X POST "$DEMO/admin/fix" -H "X-Admin-Token: $TOKEN" -H 'content-type: application/json' -d '{}'; echo; }
k() { scripts/node.sh kubectl -n anvil-demo "$@"; }
```

Keep `k get pods -w` and the guestbook open. Times are with anvil's default rules (in brackets: with
`AnvilDemoDown`); **the phone rings only if the autopilot can't fix it**: when it starts (seconds after an alert) it holds the calls; if it
fixes the problem, nobody is called. Without the autopilot, the first call comes ~2 minutes after the alert; if the
autopilot gives up, at once.

| # | Step | Time | What the audience sees |
|---|---|---|---|
| 0 | Sign the guestbook | 1 min | *pending*, then *approved* by the worker; the serving pod changes between reloads (2 replicas) |
| 1 | `brk crash` | 1 min | both web pods exit and are back within seconds (RESTARTS 1). No alert: one crash isn't an incident |
| 2 | `brk hang` | 3 min | site stops answering (Traefik 503 within ~10 s); after ~2.5 min the kubelet restarts the containers; back before `SiteDown` (5 min) would fire: no call. Liveness is slow on purpose so slow starts aren't killed |
| 3 | `brk errors` | ~6 min [~2] | 500s, pods 0/1 READY, site 503; `SiteDown` + `ServiceUnavailable` after 5 min [1 min] → the autopilot holds the calls, restarts `deploy/anvil-demo-web` → ready → resolved → **no call** (the screen shows `/autopilot`: held, then FIXED). `slow` plays out the same way |
| 4 | `brk stuck` | ~5 min | new entries stay *pending* while every pod looks healthy (alive, not working); `AnvilDemoWorkerStuck` after ~4 min → the autopilot restarts the worker → pending entries approved |
| 5 | `k set env deploy/anvil-demo-web BREAK_ON_START=1` | ~10 min (start it first, come back at the end) | the site **stays up** (`maxUnavailable: 0` keeps the old pods); once the crash-looping pod is 10 min old `PodRestartingOften` fires → the autopilot runs `kubectl rollout undo` |

### Fixing by hand

| Situation | Command |
|---|---|
| some pods broken, site reachable | `fix` |
| web pods unready (`errors`, `slow`, `hang`) | `k rollout restart deploy/anvil-demo-web`, or port-forward to a pod and POST `/admin/fix` there (it fans out) |
| worker stuck | `fix`, or `k rollout restart deploy/anvil-demo-worker` |
| bad release | `k rollout undo deploy/anvil-demo-web` (a `node.sh deploy anvil-demo` also undoes it) |
| a call already running | [stop it](/operations/silence-alerts/#stop-calls-that-already-started) |

After the talk: `fix`, check every pod is READY and the alerts have resolved.

<Aside type="tip" title="Locally, without a database">
`npm ci && npm run build && npm test`, then `DEMO_MEMORY_STORE=1 ADMIN_TOKEN=dev-only-token npm start` serves
`http://localhost:8080` (metrics on :9090). Single process: the worker won't see the web's entries in that mode.
</Aside>
