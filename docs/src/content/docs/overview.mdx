**anvil** is a platform for running many small projects (websites, APIs, bots, cron jobs) on **one** cheap cloud
server, safely enough that you can stop thinking about it. It is the cleaned-up, generic copy of a private server,
a personal server that has run about 20 real projects since October 2026. Every rule in it comes from something that
went wrong (or nearly did) on that server.

It is built to be operated by [Claude Code](https://docs.anthropic.com/en/docs/claude-code): the repo carries the
rules (`CLAUDE.md`), runbooks and skills an agent needs, a queue for the steps only a human can do (`HUMAN.md`), and
an [autopilot](/components/autopilot/) that handles incidents when nobody is watching.

## What's in the box

| Layer | What | Page |
|---|---|---|
| Server | One Scaleway instance (the original: DEV1-L, 4 vCPU / 8 GB / 80 GB local SSD) running Flatcar Container Linux and single-node k3s with Traefik, created by Terraform + Butane | [Infrastructure](/components/infrastructure/) |
| Edge | Cloudflare Free in front of every site: Origin CA certificates, Authenticated Origin Pulls with **your own CA**, firewall open only to Cloudflare, `www` → apex redirects | [Edge](/components/edge/) |
| Data | One shared MariaDB ("atlas"), one database and two users (`_rw`, `_ro`) per project; nightly off-site dumps with a write-only key | [Data & backups](/components/data/) |
| Monitoring | Prometheus, Alertmanager, blackbox exporter, kube-state-metrics, Grafana (all on Tailscale only); phone calls through Twilio | [Monitoring](/components/monitoring/) |
| Status | A small webhook service with `/overall`, `/space`, `/database`, `/backups`, `/cluster`, an error latch and the autopilot's endpoints | [Status webhooks](/components/status-webhooks/) |
| Secrets | SOPS + age: encrypted twins in git, plaintext gitignored, a pre-commit hook | [Secrets](/components/secrets/) |
| Autopilot | Claude Code in a container that diagnoses and fixes incidents within a strict allowlist | [Autopilot](/components/autopilot/) |
| Off-box | A home machine (a Mac mini works) with the watchdog, a vault for operator credentials, the autopilot and a backup pull | [Mac helpers](/components/mac-helpers/) |
| Workflow | `CLAUDE.md` rules, skills, `HUMAN.md` hand-offs, auto-commit, post-mortems | [Claude Code workflow](/components/claude-code/) |

## Real numbers (from the original platform)

| | |
|---|---|
| Projects | ~20 namespaces: static sites, Next.js apps, a Spring Boot API, Discord/Telegram bots, cron jobs |
| Server | 4 vCPU / 8 GB RAM / 80 GB local SSD (~65 GB usable for `/`), 2 GiB swapfile |
| Monitoring stack | ~140 MB RAM without Grafana; Grafana ~250–280 MiB; kube-state-metrics ~25 MB |
| Shared MariaDB | 512 MB buffer pool, `max_connections` 300, one 30 Gi volume |
| Calls | rules wait 5 min, then the first call 2 min after the alert (~7.5 min in), then 4, 6, 8, 12, 17, 22, 32, 47, 62 min, then hourly; at once if the autopilot gives up |
| Autopilot | polls every 15 s, starts after 2 bad polls, ≤ 15 min per run, ≤ 4 runs per UTC day |

## What anvil is not

- **Not highly available.** One node is the cluster. A reboot or a dead VM is downtime; the off-box watchdog makes
  sure you hear about it. Optional small worker nodes (k3s agents, tainted, off by default) are for light jobs, not
  for failover.
- **Not multi-tenant.** It assumes one owner who trusts every project on the box. Isolation between projects (own
  namespace, own UID, own DB user) limits mistakes, not a determined attacker in one app.
- **Not a PaaS.** You write a Kubernetes manifest per project. `scripts/new-site` gives you one that already follows
  the [rules](/reference/app-rules/).

## Repository layout

anvil keeps the original server's layout, so features can be copied between the two without translation.

| Path | What |
|---|---|
| `infra/` | Terraform (`*.tf`, state + encrypted twin), `butane/` (first-boot config), `manifests/` (Traefik config, origin-pull TLSOption) |
| `platform/<ns>/app.yaml` | the shared stack: `alerting`, `webhook` (status), `atlas` (MariaDB), `origin-ca`, `www`, `dozzle`; `platform/backup/` is the backup image |
| `apps/<ns>/app.yaml` | projects: the Namespace and everything in it, plus `prod.env.sops`; `apps/anvil-demo` is the demo |
| `sites.yaml` | every site's zone, hosts, `www`, probes, metrics, database, generated secrets and UID block ([format](/reference/sites-yaml/)) |
| `anvil.env` | every setting and secret (gitignored; `anvil.env.sops` in git; [Variables](/reference/variables/)) |
| `demo/` | the demo app's source (TypeScript) |
| `images/` | other images anvil builds (`twilio-alert`) |
| `mac/` | the home machine: `watchdog`, `autopilot`, `openbao`, `backup-pull` |
| `scripts/` | `node.sh` (operate the server), `anvil-secrets`, `make-secrets.py`, `secrets.sh`, `sites.py`, `new-site`, `origin-pull-ca`, `origin-certs.py`, `cloudflare-zones.py`, `cutover.py`, `build-images`, `image-tag`, `home-deploy` |
| `.claude/skills/` | the bootstrap steps `00-preflight` … `99-teardown` and `update-images` |
| `autopilot.yaml` | the platform's description for the autopilot: endpoints, secret references, extra refusals |
| `CLAUDE.md`, `HUMAN.md` | the operator's rules; the human task queue |
| `.data/` | gitignored: restore data, the origin-pull CA and Origin CA keys (encrypted twins under `secrets/`) |
| `docs/` | this site |

Everyday commands: `make check`, `make apps`, `make images`, `scripts/node.sh deploy <ns>`,
`scripts/new-site init|plan|apply`, `scripts/node.sh kubectl …`; `make help` lists the targets.

## Where it comes from

anvil is the generic version of a personal platform that has run about 20 projects since October 2026, built in about
ten days with Claude Code as the operator ([History](/history/)). That platform stays private; features flow from it
to anvil. Every rule in `CLAUDE.md` comes from something that went wrong there ([Lessons learned](/lessons/)).
