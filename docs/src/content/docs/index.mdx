anvil is the generic, reproducible version of a personal server that has run about 20 real projects
since October 2026: websites, APIs, Discord bots and cron jobs on one Scaleway VM. Everything in it was built and is
operated with [Claude Code](https://docs.anthropic.com/en/docs/claude-code) as the operator, following written rules.

<CardGrid>
  <Card title="Locked-down edge" icon="padlock">
    Only Cloudflare can reach the origin: a firewall limited to Cloudflare's ranges **and** a client certificate
    from your own CA. No ACME and no Cloudflare token on the server.
  </Card>
  <Card title="Data you can't lose" icon="database">
    One shared MariaDB with two least-privilege users per project; nightly off-site dumps uploaded with a key that
    can write but never list, read or delete.
  </Card>
  <Card title="Told when it breaks" icon="phone">
    Prometheus, Alertmanager and blackbox probes, phone calls through Twilio, and a watchdog on a second machine
    for when the server itself is gone.
  </Card>
  <Card title="An autopilot with guardrails" icon="rocket">
    Claude Code in a container that diagnoses an incident and may only restart, roll back, re-run a job or delete one
    stuck pod, then writes a post-mortem.
  </Card>
  <Card title="Secrets in git" icon="code-branch">
    SOPS + age: plaintext gitignored, encrypted twins committed, a pre-commit hook that refuses stale or leaked
    secrets. One key is the root of trust.
  </Card>
  <Card title="Reproducible" icon="server">
    Terraform + Butane for the node, one manifest per project, `sites.yaml` as the single list of sites. A fresh
    server is a rebuild, not an archaeology project.
  </Card>
</CardGrid>

## What anvil is not

<CardGrid>
  <Card title="Not highly available" icon="warning">
    One server is the whole platform: a reboot or a dead VM is downtime. The watchdog on a second machine makes sure
    you hear about it; it doesn't keep the sites up.
  </Card>
  <Card title="Not multi-tenant" icon="error">
    It assumes one owner who trusts every project on the box. Each project's own namespace, user and database login
    limit mistakes, not a determined attacker inside one app.
  </Card>
  <Card title="Not a PaaS" icon="seti:yml">
    No push-to-deploy: every project is a Kubernetes manifest you (or Claude Code) write. `scripts/new-site` gives you
    one that already follows the rules.
  </Card>
  <Card title="Not hands-off" icon="phone">
    The phone can ring at night. The autopilot fixes the easy incidents only, OS updates are run by hand, and new
    sites still need a person for DNS.
  </Card>
  <Card title="Not cloud-agnostic" icon="cloud-download">
    It's built on Scaleway, Cloudflare (Free), Twilio and Tailscale. Moving to another provider means rewriting
    `infra/`, not changing a setting.
  </Card>
  <Card title="Not for big workloads" icon="rocket">
    One VM and one shared MariaDB suit many small projects. A site that outgrows it can move to its own pool node
    for a while, but this is no cluster for heavy traffic.
  </Card>
</CardGrid>
